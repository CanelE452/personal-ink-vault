## 태블릿 빈 화면·PDF 실패 복구·Drive 인증 수정

- 사용자가 S9+에서 앱은 열리지만 새 노트/PDF에 빈 화면이나 오류가 발생하고 Drive도 동작하지 않는다고 보고했다. 현재 USB 연결은 어렵고 정확한 오류 문구는 받지 못했다. 따라서 아래는 호스트에서 재현한 결함이며 사용자 기기의 원인을 확정하거나 실기기 해결을 선언하지 않는다.
- [확인] Android 화면 분기의 실제 StudyWorkspace→Editor 회귀시험에서 `CanvasGestureDetector.initState`가 이미 로드된 노트의 `MediaQuery`를 너무 일찍 읽어 assertion이 발생했다. 최초 변환을 첫 레이아웃 뒤로 옮기고 폐기 여부를 확인하도록 수정했다. 편집 역할은 테마 설정과 분리된 `defaultTargetPlatform`으로 판정한다.
- [확인] PDF 최초 읽기 실패 뒤 dirty/busy가 남아 노트 전환까지 막히는 경로를 재현했다. Editor에 명시적 가져오기 취소를 추가하고 WorkspaceController가 마지막 완전 저장본의 새 세션으로 복구하도록 했다. 원본 PDF·기존 리비전을 삭제하지 않으며 이전 세션의 늦은 저장은 거부한다. 실패한 PDF 캐시를 dispose할 때 같은 오류가 다시 전달되던 문제도 재현·수정했다.
- 새 노트/기존 노트 열기는 Scaffold의 Drawer만 닫도록 바꿨다. 실패 알림도 열린 Drawer에 가려지지 않도록 했다. 수정 파일은 `editor.dart`, `study_workspace.dart`, `workspace_controller.dart`, `canvas_gesture_detector.dart`, `pdf_document_cache.dart`와 관련 회귀시험이다.
- [확인] Drive 자동 복원은 계정 선택 UI를 열 수 있는 lightweight 인증 대신, 수동 로그인 후 보안 저장한 계정 ID·이메일에 묶인 `promptIfUnauthorized: false` 승인 요청으로 바꿨다. 고정 Android 플러그인 소스에서 이 요청이 Activity 없이 application context를 사용하는 경로임을 확인했다. 토큰은 앱 파일에 영구 저장하지 않는다. 기존 설치는 업데이트 후 로그인/재연결을 한 번 직접 실행해야 한다.
