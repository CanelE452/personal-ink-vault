## 폴더 홈·문서 편집·Rust 확대 요청 검토

- 사용자가 preview.2 사용 후 뒤로가기와 문서 홈을 지적하고 StarNote식 폴더/표지/생성 메뉴·필기 도구, Obsidian 기능, Office·한글의 PDF/실제 원본 편집, Rust와 기기 공통 사용을 요청했다. 사진은 기존과 같이 Git 제외 개인 첨부로 둔다.
- [확인] SaveIndicator가 옛 home 경로로 이동해도 router가 workspace로 redirect하고 activeSession은 유지하므로 뒤로가기가 문서를 닫지 않는다. 시스템 뒤로가기에도 저장 후 세션 종료 계약이 없다. 현재 홈은 안내문/목록만 있고 폴더·문서 종류·표지 모델은 없다. 생성된 항목과 빈 노트 사진만으로 PDF 원본 유실을 확정하지 않았다.
- 현재 v1 parser와 rename/delete writer는 새 폴더 유형/필드를 안전하게 유지하지 못한다. 실제 동기화 폴더에는 명시적 형식 확장·이전/복원 시험이 필요함을 확인했다. 썸네일은 원본 리비전별 로컬 재생성 캐시로 제안했다.
- 공식 자료를 확인해 Flutter 화면+Rust 공통 핵심을 권고했다. Android/Windows 지원 자체는 Rust로 바꿔야 얻는 것이 아니며 iOS는 별도 환경/검증이 필요하다. ONLYOFFICE 모바일 서버/상용 통합과 HWP/HWPX 보기·변환 범위, 한컴 SDK의 별도 제공 범위를 구분했다. 상세 출처는 새 `docs/library-workspace-design.md`에 남겼다.
- 새 설계안과 requirements의 최신 요구 기록을 작성했다. 제품 코드·패키지·저장 형식·Cloud·실제 개인 문서는 변경하지 않았다. Rust 범위와 전체 단계 순서 확정 전이며 commit/push·새 APK 빌드는 하지 않았다.
- 독립 설계 검토에서 문서 카드와 Markdown 관계, 폴더 삭제 의미의 두 공백을 발견했다. 기존 쌍은 한 카드로 보존하고 새 Markdown은 독립 문서로 생성하며, 폴더는 관측한 하위 항목과 휴지통/복원하는 작성자 기본안을 명시했다. 재검토에서 별도의 중요 질문은 남지 않았고 Rust 범위·순서·Office 조건은 사용자 결정으로 남겼다.
- 사용자의 기업 사례 후속 질문에 1Password8(2021)의 Rust 공통 코어+플랫폼별 UI, Dropbox Nucleus(2020)의 Rust 동기화 엔진, Figma(2023)의 React/TypeScript UI·C++/WASM 캔버스·Rust 공동 편집 서버를 공식 자료로 확인해 설계안에 추가했다. 각 공개 시점의 사례이며 현재 전체 내부 구성을 단정하지 않았다.

## 기존 MVP 뒤로가기 수정

- 확대 기능의 합의와 별도로 기존 뒤로가기 결함을 수정했다. SaveIndicator/Editor에 선택적 workspace callback을 연결하고 내부 legacy PopScope를 우회했다. 화면/시스템 뒤로가기는 실제 Editor 저장→controller flush→직렬화된 세션 닫기→기존 목록으로 연결된다. 좁은 화면은 목록 Drawer를 열고, 열린 Drawer는 먼저 닫으며 홈에서는 OS 기본 뒤로가기를 유지한다.
