# 요구사항

## 2026-11-08 지원 기기 확정

지원과 검증 대상은 Android 휴대폰·태블릿과 Windows PC다. 필기 수용 시험은 Galaxy Tab S9+와 S Pen을 기준으로 진행하고, 두 플랫폼의 실제 Google Drive 왕복은 별도로 검증한다.

## 2026-10-30 확대 요청 — 실제 조사 후 구현 중

사용자가 폴더·문서 표지 홈과 생성 메뉴, StarNote를 참고한 필기 화면, Obsidian식 지식 연결, Office·한글의 PDF 필기/원본 편집 모드, Rust 사용과 휴대폰·태블릿·PC 공통 사용을 요청했다. 이어서 추가 질문 없이 실제 역공학 후 구현하고, StarNote 참조가 부족하면 비슷한 다른 앱도 참고하라고 지시했다. 이에 Flutter 화면+Rust C ABI 공통 핵심을 선택해 v2/폴더·Drive 형식 분리, 홈·지식·무한 필기·썸네일·Office 통합을 개발 중이다. [확대 설계](library-workspace-design.md)와 [구현 체크포인트](library-workspace-plan.md)에 구현·통합·실기기 검증을 구분한다. 요구 전체가 끝난 상태는 아니며 최신 로컬 APK·Windows 묶음과 공개 배포 상태는 [검증 기록](mvp-validation.md)에 구분한다.

실제 앱 안의 PPT/PPTX·DOC/DOCX·HWP/HWPX 원본 편집과 PDF 필기 모드를 모두 목표로 유지한다. PDF 변환이나 외부 앱 실행만으로 원본 편집을 완료했다고 표시하지 않는다. 현대 HWP5/HWPX 처리, Android Office 실행, S9+ 필기와 Windows 사이의 Drive 왕복은 계속 남은 수용 조건이다. 무한 필기와 Obsidian식 카드 캔버스도 서로 다른 기능이다. 현재 지식 패널/무한 필기의 일부 시험 통과를 이 전체 요구의 완료로 확대하지 않는다.

### build52 현재 검증 경계

[확인] 로컬 build52는 Android Office의 상태별 뒤로가기·사진 선택 callback, 원본 탭의 선택 PDF 첫 페이지·명시적 read-only 변환을 포함한다. 미리보기는 판본/필기 기록을 공개하지 않고, PDF 필기 시작에만 같은 PDF를 공개한다. 전체1141PASS/108skip/0FAIL·분석0과 새 APK/Windows 설치 묶음 검증을 통과했다. native JDK/stub·컴파일·APK bytes 확인을 실제 S9+/JNI로 확대하지 않는다. Windows 사진 삽입·삭제·객체 교체 이동은 합성 native 관측이며 일반 제품 API로 완료한 기능이 아니다. 전체 요구와 남은 실기기·Drive·Office/Notion 범위는 유지한다.

## 2026-10-22 후속 합의

사용자는 **Galaxy Tab S9+ PDF 필기 → Windows에서 보며 Markdown 정리 → Drive 자동 동기화**를 첫 MVP로 확정하고 세 앱 분석 반영과 개발 시작을 승인했습니다. 아래 R1–R9는 장기 요구 목록이며 현재 범위는 [MVP 설계](mvp-design.md)를 따릅니다. 당시 태그·일반 역링크·그래프·AI·OCR·StarNote 가져오기는 후속 제안이었습니다. 실제 앱 검증 범위는 [검증 기록](mvp-validation.md)에 구분합니다.

## 사용 목적과 범위

Android StarNote 손필기에서 느끼는 PC 활용의 불편을 줄이고, 한 사람이 여러 기기에서 필기·PDF·Markdown 지식을 연결합니다. Android 휴대폰의 터치·읽기·편집과 펜을 지원하는 태블릿의 필기 경험을 각각 검증합니다.

초기 조사 단계 이후 앱 구현·도구 설치·OAuth 설정·preview APK 배포가 진행됐으며 현재는 위 확대 구현을 진행합니다. 실제 앱 로그인/계정 동의와 두 기기 전송 수용은 별도로 검증해야 합니다. 개인 자료의 원격 대상은 비공개 Drive이며, 새 문서 처리 서버나 AI 공급자에 개인 자료를 보내는 것은 현재 구현 완료의 전제가 아닙니다.

## 필수 기능과 향후 검증 기준

- **R1 필기:** 펜·형광펜·지우개, 실행 취소/다시 실행, 확대·이동. 지원 펜의 압력·기울기, 손바닥 오입력, 지연을 실기기에서 기록합니다. 획 단위/부분 지우개 세부 방식은 설계 때 결정합니다.
- **R2 PDF:** 원본을 바꾸지 않는 별도 주석 레이어. 페이지 크기·회전·순서와 필기 좌표를 보존하고 재열기·내보내기에서 위치가 맞아야 합니다. 기존 PDF 주석의 편집 가능 여부는 별도 조사입니다.
- **R3 텍스트:** Markdown과 수식 작성·미리보기·내보내기. 현재 Flutter Markdown·수식 렌더러를 사용하며 확대 기능의 호환성을 계속 검증합니다. 링크된 문서나 HTML이 임의 스크립트를 실행하지 않도록 합니다.
- **R4 지식 연결:** 생성 시 부여한 고정 `noteId`로 링크·역링크를 구성합니다. 제목/파일명 변경에도 연결이 유지되어야 합니다. 태그·제목·본문 검색과 로컬 그래프를 지원하며, OCR/손글씨 내용 검색은 별도 후속 기능입니다.
- **R5 AI 설명:** 필기와 AI 설명을 분리합니다. 설명은 노트 ID·원본 리비전·페이지/영역을 참조하며 원본 획을 덮어쓰지 않습니다. 생성 주체·시점·근거를 표시하고, 원본 수정 후 설명의 오래됨을 구분합니다. AI 공급자·실행 방식은 미선정이며 외부 전송은 별도 선택 대상입니다.
- **R6 오프라인:** 생성·편집·검색·저장·재열기가 네트워크 없이 동작해야 합니다. 중간 종료·저장 실패·용량 부족에서 기존 데이터가 남아야 합니다. AI 생성의 오프라인 가능 여부는 선택 모델에 따라 별도로 결정합니다.
- **R7 백업/복원:** 버전 있는 전체 내보내기, 무결성 검사, 빈 저장소로의 복원과 마이그레이션을 검증합니다. 첨부파일·링크·AI 설명까지 함께 복구하고, 복원 실패 시 기존 데이터는 보존합니다.
- **R8 동기화:** R6·R7 이후 진행합니다. 두 기기의 동시 편집, 첨부파일 중복/중단 전송, 기기 시계 차이, 삭제 기록과 복구, 장기간 오프라인 후 합류를 다룹니다. 최근 시각 하나로 덮어쓰지 않으며 충돌 사본과 복구 경로를 보존합니다.
- **R9 Google Drive 저장:** 개인 필기·PDF·백업을 GitHub와 분리해 Drive에 저장하는 구조를 설계합니다. 로컬 오프라인 저장을 유지하며 첫 MVP에 자동 양방향 전달을 포함합니다. 충돌 사본·삭제 복구·독립 백업은 별도 구현해야 하고 실시간 획/문자 병합은 첫 범위가 아닙니다. Drive에 파일을 올릴 수 있다는 사실만으로 동시 편집 병합·삭제 복구·자동 동기화가 해결되지 않습니다.

## 데이터 원칙 — v1 보존과 v2 확대 구현

- 노트·페이지·획·첨부파일·AI 설명에 독립 식별자와 스키마 버전을 둡니다. 제목·경로·기기 시각을 식별자로 쓰지 않습니다.
- 원본 필기, 원본 PDF, Markdown, 주석, AI 설명을 논리적으로 분리합니다. 검색·역링크·그래프 인덱스는 원본에서 재구성할 수 있어야 합니다.
- 첨부파일은 내용 해시 등으로 무결성을 확인합니다. 암호화·키 보관·동기화 서버는 미선정이며 이 단계에서 키를 만들지 않습니다.
- 개발 저장소와 개인 vault/백업 경로를 분리합니다. 합성 예시는 `테스트 노트 A`처럼 개인정보 없는 내용만 사용합니다.
- 공개 가능한 앱 ID·OAuth client ID·리디렉션 설정 예시와 비밀정보를 구분합니다. client secret·access/refresh token·서명 키·계정 설정은 GitHub에 넣지 않고 기기 보안 저장소 등 별도 보관 방식을 검토합니다. 권한 범위·암호화·복구 키는 Drive 접근 방식 선택 후 설계하며 지금 생성하지 않습니다.

## StarNote 호환성의 독립 단계

1. 파싱: `.note` 구조와 페이지·획·스타일·첨부를 손실 보고서와 함께 읽기.
2. 보기/변환: 원본 화면과 비교해 렌더링 또는 PDF 출력의 일치 검증.
3. 편집: 가져온 획을 개별 선택·이동·삭제·저장·재열기.
4. 왕복: 다시 `.note`로 저장한 결과를 StarNote가 정상적으로 열고 편집하는지 검증.

현재 네 단계 모두 미검증입니다. 이미지/PDF 변환 성공을 편집·왕복 호환 성공으로 간주하지 않습니다. 자세한 근거는 [호환성 조사](compatibility-research.md)를 참고합니다.

## 제외 범위

구독/인증 우회, 타인 데이터 추출, APK 무단 패치, 다른 앱 라이브 데이터 수집, Obsidian 코드 복제, 임의 스킬 설치는 하지 않습니다. StarNote 무손실 호환과 실제 동기화는 각각 수용 시험을 거칩니다.

## 2026-10-30 추가 요청 — Notion의 유료 기능까지 자체 구현 범위에 포함

사용자가 Notion의 기능과 유료 플랜에 있는 기능도 이 앱 안에서 구현해 달라고 요청했다. 기존 필기·Office·Obsidian식 연결·Android/Windows·Drive 목표를 유지하고 블록 페이지, 속성 데이터베이스와 여러 보기, 관계/롤업/수식, 조건부 폼·템플릿·버튼·자동화, 이력/댓글·협업권한, AI 작성/근거 검색/회의록·에이전트, 발행/외부 연결, 기업 관리 계층까지 단계적으로 확대한다. [공식 기능 조사와 구현 계약](notion-feature-scope.md)에 현재 Notion 공개 목록, AppFlowy 고정 공개 소스 참조, 자체 앱의 저장/충돌 경계와 수용 조건을 기록했다.

‘유료 기능 포함’은 자체 앱의 동등 기능을 개발하는 범위다. 현재 구현에 없는 서버 권한·실시간 공동 편집·AI/음성 모델·상시 자동화·SSO/SCIM을 이미 제공한다고 표시하지 않는다. 블록/DB 등 로컬 기능부터 연결하며, 외부 실행 환경·계정/권한·자료 처리 조건이 필요한 기능은 실제 연동과 수용까지 별도 단계로 남긴다. 기존 개인 Drive 전달을 기업 협업·행 접근 제어의 완료로 간주하지 않는다. 이 추가 요구는 기존 R1–R9의 AI/지식/협업 기능을 장기 제안에만 머무르게 하지 않고 구현 목표에 포함하며, 일부 모듈의 시험 통과를 전체 Notion 동등성의 완료로 확대하지 않는다.
