# 저장된 페이지·데이터베이스 내보내기

문서 내보내기는 build61부터 제공하며 **현재 build62 Windows ZIP·Android APK에도 포함**됩니다. build62는 [글자 범위 서식과 링크](inline-rich-text.md)의 내보내기도 포함합니다. [현재 설치 후보](../README.md)의 링크는 이 PC 전용이며 GitHub에는 게시하지 않았습니다. 이전 build60에는 없습니다. 실제 build62 설치 폰트를 사용한 host 검증은 통과했지만 standalone GUI·Android 실기기 수용은 남아 있습니다.

1. 일반 페이지 또는 데이터베이스를 엽니다.
2. 상단 다운로드 아이콘 **문서 내보내기**에서 Markdown·HTML·PDF를 선택합니다. CSV는 데이터베이스에서만 보입니다.
3. 앱이 작성 중인 내용을 먼저 저장하고 한 저장 판본을 준비합니다. 저장에 실패하면 내용을 확인한 뒤 다시 시도합니다.
4. 저장창에서 ZIP 파일 위치를 선택합니다. 취소하면 성공 안내를 표시하지 않으며 저장한 노트는 유지합니다.
5. ZIP 전체를 한 폴더에 풀고 제목과 문서 ID가 붙은 `.md`·`.html`·`.csv`·`.pdf` 파일을 엽니다.

압축 파일에는 다음 항목이 함께 들어갑니다.

- 주 문서: 선택한 형식의 본문 또는 DB 표입니다.
- `rows/`: DB 각 행의 본문입니다. 보관된 행도 포함합니다.
- `media/`: 이미지와 첨부 원본입니다. 문서와 같은 폴더 구조로 보관하세요.
- `source/`: 선택한 저장본의 구조화 snapshot 파일을 원래 bytes로 보존합니다. 안전하지 않은 이름은 바꾸고 보고서에 대응 위치를 기록합니다.
- `export-report.json`: 문서·본문/metadata 판본, 파일별 크기/SHA, 계산 결과·시각·관계 입력 판본과 변환 경고입니다.
- `읽어주세요.txt`: 이 묶음의 열기 방법과 범위 안내입니다.

PDF의 한글은 검색·선택할 수 있는 텍스트로 만듭니다. 긴 문서와 표는 여러 쪽으로 나눕니다. 폰트가 지원하지 않는 글자는 코드 표기와 경고로 남깁니다. 첨부는 PDF 내부에 넣지 않고 ZIP의 `media/`에 별도 보관합니다.

CSV는 UTF-8 BOM을 포함하며 수식처럼 실행될 수 있는 문자열에는 안전한 접두사를 붙입니다. 이 변경과 계산 오류를 보고서에 기록하며 원래 값은 `source/`에 남습니다.

DB 계산값은 내보낸 시점의 고정 결과입니다. 수식·관계 정의와 뷰·폼·자동화는 원본 JSON에 보존하지만 내보낸 파일에서 앱처럼 실행되지는 않습니다. 외부 문서·관계 DB와 원격 URL 파일은 자동으로 함께 내려받지 않습니다. `export-report.json`의 경고를 확인하세요.

이 ZIP은 **선택한 한 저장 판본**입니다. 전체 vault 백업/복원이나 대용량 streaming export와 구분하며 기존128MiB snapshot 입력 한도를 유지합니다. PDF·필기·Office 원본은 이 페이지/DB 메뉴의 대상이 아닙니다.
